01

The big picture

You are not building a phone app. You are building a small website with a brain behind it. The website makes digital cards. Apple Wallet and Google Wallet, which are already on every phone, hold those cards for you.

Piece 1

Join page

A web page the guest opens by scanning a QR code. They type their name and number and tap Add to Wallet.

Piece 2

Card maker

Code on your server that builds the card for iPhone and for Android and keeps it up to date.

Piece 3

Staff scanner

A web page staff open on any phone. It scans the guest's card and adds a stamp or points.

Piece 4

Owner dashboard

A web page where the owner sees members and sends offers. You also get an admin page to add new venues.

The one rule that makes this a business

Nothing about a venue is written in the code. Name, colours, logo, rewards and location all live in the database.

That is what lets you sign a café on Monday and hand them a working card on Tuesday.

Words to know

WordWhat it means in plain language
PassThe digital card inside Apple Wallet or Google Wallet.
Server / backendYour code running on a computer on the internet. It makes and updates passes.
DatabaseAn online spreadsheet your code reads and writes: venues, members, visits.
APIA way for two programs to talk. Your server talks to Apple and Google through their APIs.
CertificateA digital signature from Apple that proves a pass really came from you.
.pkpassThe file type of an Apple pass. It is a zip with a few images and one text file inside.
PushA silent message from your server telling a phone "this card changed, fetch the new one".
DeployPutting your code online so anyone can use it.
Environment variableA secret (like a password or key) stored outside the code so it is never shared by mistake.

Technology choices

The stack, and why

  • Next.js with TypeScript: one project holds the web pages and the server code, and it deploys to Vercel in one click.
  • Supabase (Postgres): database, login and image storage in one place.
  • passkit-generator: a free library that builds and signs Apple passes.
  • google-auth-library and jsonwebtoken: talk to the Google Wallet API.
  • html5-qrcode: turns a phone camera into the staff scanner.
  • Tailwind CSS: styling for the pages in the aikia look.

You know Python, and the pass-making part could be written in it. JavaScript is recommended here because the pages and the server then live in one project, which is simpler to put online.

04

How the system flows

A guest joins

ScanGuest scans the QR. It opens wallet.aikia.world/join/cafe-noor.
Sign upThey enter name and phone. Server saves a member row.
Make the cardServer reads the venue's style and builds the pass for that phone type.
AddGuest taps Add to Wallet. The phone tells your server "I hold this card".

A guest pays and earns

ShowGuest opens the card. It shows a QR with their member ID.
ScanStaff scan it on the scanner page and tap Add stamp.
SaveServer records the visit and works out stamps, tier and rewards.
UpdateServer pushes the change. The card on the phone refreshes in seconds.

The café brings them back

HaloThe card carries the café's map location. The phone itself shows the card on the lock screen when nearby.
OfferOwner taps Fill My Tables. Server updates every member's card with the offer text.
NotifyEach phone shows a notification because a field on the card changed.
ExpireA timer removes the offer after 45 minutes.
05

Build steps

Eight steps in order. Each one ends with something you can see working. Do not start a step until the one before it works.

STEP 0 · DAY 1

Open the accounts

  1. Enrol in the Apple Developer Program at developer.apple.com. Enrol as an individual to start. Approval can take a day or two, so do this first.
  2. Open a Google Cloud account and a Google Pay and Wallet Console account. You get an Issuer ID.
  3. Create free accounts on GitHub, Vercel and Supabase.
  4. Install Node.js (the LTS version). Check it with node --version in the terminal.
Done when: you can log in to all five and the terminal prints a Node version.
STEP 1 · DAY 2

Create the project

  1. In the terminal run npx create-next-app@latest aikia-wallet. Choose TypeScript, Tailwind and App Router.
  2. Open the folder in VS Code. Run npm run dev and open localhost:3000.
  3. Push the code to a new private GitHub repository.
  4. In Vercel, import that repository. You now have a live web address.
  5. In Supabase, create a project and run the table script from section 06.
Ask your AI assistant

"Set up a Next.js App Router project with TypeScript, Tailwind and the Supabase client. Create the SQL for these tables: [paste section 06]. Put all secrets in .env.local."

Done when: your site opens at its Vercel address and the tables exist in Supabase.
STEP 2 · DAYS 3–4

Make your first Apple pass

  1. In the Apple Developer site go to Certificates, Identifiers and Profiles. Create a Pass Type ID, for example pass.world.aikia.wallet.
  2. On your Mac open Keychain Access and create a Certificate Signing Request. Upload it to Apple and download the pass certificate.
  3. Export the certificate and its key, and download Apple's WWDR certificate. Convert them to .pem text and store them as environment variables.
  4. Create a template folder with pass.json, icon.png, logo.png and strip.png. Use the pass style storeCard.
  5. Write an API route that uses passkit-generator to fill the template, sign it and return a .pkpass file.
  6. Open that route in Safari on an iPhone. The card should offer Add.
Ask your AI assistant

"Write a Next.js route GET /api/pass/apple/[serial] that uses passkit-generator to build a storeCard pass from a venue and member in Supabase. Read certificates from environment variables. Include a QR barcode with the member ID."

Done when: a card with the aikia look sits in Apple Wallet on a real iPhone.
STEP 3 · DAYS 5–6

Make your first Google pass

  1. In Google Cloud, create a project and switch on the Google Wallet API.
  2. Create a service account and download its key file. Add that account as a user in the Wallet Console.
  3. Write code that creates a Loyalty Class (the venue's card design) and a Loyalty Object (one member's card).
  4. Sign a small token (a JWT) and build the link pay.google.com/gp/v/save/…. That link is the Add to Google Wallet button.
  5. Test on an Android phone. New accounts start in demo mode, where only your test accounts can add cards.
Ask your AI assistant

"Write a function that creates or updates a Google Wallet LoyaltyClass per venue and a LoyaltyObject per member, then returns a signed Add to Google Wallet link. Use the service account key from an environment variable."

Done when: the same card sits in Google Wallet on a real Android phone.
STEP 4 · DAYS 7–10

Build the join page. This is your demo.

  1. Create the page /join/[venue]. It loads the venue's name, logo and colours from the database.
  2. Add a short form: name, phone number and a consent tick box.
  3. On submit, save the member, then show the Add to Apple Wallet or Add to Google Wallet button based on the phone type.
  4. Make a QR code that points to the page and print it on a small stand.
  5. Add a demo venue called "Your Café" that you can rename in ten seconds before each meeting.
Done when: a stranger can scan your QR and have the card in their wallet in under 20 seconds. You can start visiting venues from here.
STEP 5 · WEEK 2

Scanner and live card updates

  1. Build /scan. Staff log in with a venue PIN. The camera reads the card's QR with html5-qrcode.
  2. After a scan, show the member's name, tier and usual order, with buttons: Add stamp, Redeem reward, Use balance.
  3. Add the five Apple web service routes (listed in section 06). These let iPhones register and fetch the newest card.
  4. When data changes, send a push through Apple's push service so the card refreshes. For Google, call the API to update the object.
  5. Set a change message on the stamps field so the guest sees "You now have 7 stamps".
Ask your AI assistant

"Implement the Apple Wallet web service: register device, unregister device, list updated serials, get latest pass, and log. After a visit is saved, send an APNs push to every device registered for that pass and patch the Google LoyaltyObject."

Done when: you scan a card and watch the stamp count change on both phones within seconds.
STEP 6 · WEEK 3

Halo, offers and the owner dashboard

  1. Halo: add the venue's latitude and longitude to the Apple pass (locations with a relevantText message) and to the Google class (merchant locations).
  2. Fill My Tables: a button that writes an offer onto every member's card for that venue and removes it after 45 minutes.
  3. Dashboard: build /dashboard with total members, visits this week, top guests and guests who have not visited in 21 days.
  4. Automation: a daily scheduled job for birthdays, win-back offers and tier upgrades.
  5. Tiers: switch the card's colours and strip image when a member moves from Ink to Chrome to Pink.
Done when: the owner view shows real numbers and pressing the offer button lights up your test phones.
STEP 7 · WEEKS 3–4

Turn it into a template

  1. Build /admin for yourself only: a form that creates a new venue.
  2. The form takes name, colours, logo, strip image, address, map pin, reward rule and staff PIN.
  3. On save, the system creates the join page, the QR code and the Google class automatically.
  4. Create a second and third fake venue and check that nothing from one leaks into another.
Done when: you can add a brand-new venue from the form and get a working card without touching code.

Server routes

POST /api/join                      save member, return add-to-wallet links
GET  /api/pass/apple/[serial]       build and sign the .pkpass file
GET  /api/pass/google/[memberId]    return the Add to Google Wallet link
POST /api/scan                      record a visit, update stamps, push update
POST /api/campaign                  send an offer to a venue's members
GET  /api/cron/daily                birthdays, win-back, tier upgrades

GET    /api/apple/v1/passes/[passType]/[serial]

07

Adding a new venue after a sale

Once the template is built, onboarding should take one to two hours of your time per venue.

Collect from the owner

The venue sheet

  • Logo as a PNG with a clear background
  • Two or three brand colours as hex codes
  • One wide photo for the card strip (1125 × 369 px for Apple)
  • Address and map pin (right-click in Google Maps to copy latitude and longitude)
  • Reward rule, for example 9 stamps = 1 free coffee
  • Tier rules, for example Chrome at 15 visits
  • The Halo message and a welcome offer
  • Opening hours and a staff PIN
You do

Go-live checklist

  1. Fill in the admin form and upload the images.
  2. Add the card to your own iPhone and Android to check the look.
  3. Print the QR stand and table tents.
  4. Show staff the scanner and do three practice scans.
  5. Send the owner their dashboard login.
  6. Stand at the counter for the first hour and sign up the first members yourself.
08

Test and launch

Before the first real venue

Test list

  • Join works on iPhone Safari and Android Chrome
  • Scan updates both phones within seconds
  • Walk away and back to the pin: Halo card appears on both phones
  • Offer arrives, then disappears after it expires
  • Deleting the card stops updates without errors
  • Venue A staff cannot see Venue B members
  • Wrong PIN and bad QR codes are rejected
  • Slow café Wi-Fi still completes a scan
Going live

Launch list

  • Request publishing access in the Google Wallet Console so any Android user can add cards. Allow a few days for review.
  • Move to Vercel Pro and Supabase Pro.
  • Point wallet.aikia.world at Vercel.
  • Publish privacy policy and terms pages.
  • Set a calendar reminder: the Apple pass certificate expires yearly and must be renewed, or cards stop updating.
  • Turn on database backups.

09

Limits to know before you promise anything

TopicWhat is trueWhat to do
Halo distanceYou give the map pin. The phone decides when "nearby" is, roughly 100 m on iPhone. Apple lets you make it smaller, not larger.Sell it as "when they are near", not as an exact number of metres.
Halo is quietThe nearby alert is a silent card on the lock screen. It does not buzz.Use a normal push message for offers that must be seen.
Locations per cardUp to 10 on Apple and 10 on Google.Plenty for one venue or a small chain.
Google message limit3 notifications per card in 24 hours.Your own cap of one a day keeps you well inside it.
You never see locationThe wallet does not tell your server where a guest is.Offers go to all of a venue's members, not only those nearby.
PaymentsThis card does not move money through a bank. Prepaid balance is a number in your database that the café collects for at the counter.Keep balances tied to one venue and get the legal check done before switching this feature on.
Personal dataYou hold names and phone numbers.Consent tick box, a delete-my-data option, and never share one venue's list with another.
